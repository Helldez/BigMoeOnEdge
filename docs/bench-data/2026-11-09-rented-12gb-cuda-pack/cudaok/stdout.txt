# Out-of-Order Execution in Modern CPUs

## The Core Problem

A naive in-order CPU fetches, decodes, and executes instructions strictly in program order. If instruction 5 is a long-latency load from main memory (hundreds of cycles), instructions 6, 7, 8… all stall behind it even if they are completely independent. Out-of-order (OoO) execution solves this by letting the CPU **execute instructions as soon as their operands are ready**, while still **retiring them in program order** so the architectural state is always consistent.

The three mechanisms you asked about—register renaming, the reorder buffer, and branch prediction—are the pillars that make this possible.
